# Anki integration validation

The Japanese preset requires Word, Word Reading, Word Furigana, Word Meaning, Word Audio, Vietnamese Sound, Sentence, Sentence Furigana, Sentence Meaning, Sentence Audio, JLPT, Notes, and Picture. Choose an existing deck and note type; enabling the preset does not import or modify notes by itself.

Vocabulary → Sync with Anki builds a read-only preview. Choose any field conflicts, then apply the selected entries. Imports bypass dictionary enrichment and generated examples. Existing links use note IDs within the active Anki profile; ambiguous initial matches require selection. No deletion crosses between apps. Hidden local entries can be explicitly selected for reimport. Anki templates and deck options are never rewritten.

The dialog shows 50 changes per page, with separate page and total selection. Stop cancels preview reads immediately. During apply, it finishes the current note, read-back, local save, and journal, then starts no further notes. Completed imports remain available, and the result separates completed, failed, and not-attempted notes. Full-deck progress refresh is deferred after stopping. Refresh the preview to resume; existing note links prevent duplicate imports. Connection-wide failures end the batch after the first affected note.

Learned words and locally dictionary-confirmed inflections are bolded in matching Sentence and Sentence Furigana fields. Ruby readings, punctuation, visible text, and existing formatting are preserved; uncertain compounds and mismatched sentences are left alone. Vocabulary loading repairs existing local entries idempotently, without changing their Anki baseline. Imports, mining, and editor saves use the same helper. These formatting differences appear in the next manual sync preview; no bulk write is made to Anki.

Word and sentence cells have separate recording buttons. Multiple sound references play in order through one shared player; clicking again, changing displayed rows, or leaving the view stops playback. Media comes from the profile-specific cache or the matching active Anki profile. Uploads and unlinking retain the recording profile locally. No TTS fallback is used. Uncached files require AnkiConnect; cached recordings remain available offline.

These Anki paths make no language-model requests and have no model token cap. The dictionary refinement budget bounds lookups only: after 128 distinct lookups, unconfirmed tokens remain unchanged. The 24-character candidate-word bound also retains the original token. Neither limit truncates sentence fields or imports. Regression tests cover exhausted lookup budgets, 1,500 ruby-highlighted occurrences with the tail preserved, 251-note imports across 100-note batches and 50-row pages, and a 54,003-character Notes field. Incomplete preview responses fail before saving anything. A progress-refresh error is reported separately from failed notes after content has been saved.

The review source uses the `Word` and `Word Audio` template names. Sessions contain up to 50 due/new cards, due first, excluding suspended, buried, and filtered cards. Ordering and daily limits are Hakkutsu's session behavior, rather than Anki's native queue order. Anki handles each submitted rating and resulting schedule. There is no offline review queue and no historical local-review import. The aggregate local vocabulary status records maturity and due-now only; Anki day-number due values are never treated as Unix timestamps.

Each answer requires reveal and a confirmed API response before advancing. An uncertain submission remains pending; checking review history can confirm it without resubmitting. If there are multiple intervening reviews, check Anki and refresh instead of retrying automatically. Manual release is available only after checking an unrecorded operation. AnkiConnect has no transaction spanning profile switches, edits in Anki, and an answer, so avoid simultaneously reviewing the same card in both apps.

Before applying sync, Hakkutsu stores a recovery snapshot. The download includes local content/progress, cached media, sync state, and original Anki note values. Restore merges local data and marks links unverified; it never rolls back Anki automatically. First-link local review progress is also archived on the link and restored when unlinking. Version 1 backups remain supported. Only cached media is included; missing Anki media is reported and retained as a reference. Media uploads happen when a file is selected, before saving the vocabulary edit.

## Automated checks

- `node --test tests/*.test.cjs`: Anki tests cover fields/ruby, three-way merge, duplicate identities, repeated sync, stale previews, profile isolation, interrupted writes, pending answers, progress archival, strict search syntax, cancellation, lock release, partial imports, resuming, local highlighting baselines, and sequential/switching/error playback.
- `node node_modules/typescript/bin/tsc --noEmit`.
- `node node_modules/wxt/bin/wxt.mjs build` and `node node_modules/wxt/bin/wxt.mjs build -b firefox`.
- Start `node node_modules/vite/bin/vite.js --config tests/vite.config.ts`, then run `node scripts/test-anki-browser.mjs`. `CHROME_PATH` can override the Windows Chrome path. The runner uses a fresh browser profile, real IndexedDB and production React components, and a page-local simulated Anki API. It never contacts the user's Anki collection.
- The fixture renders the actual vocabulary toolbar/table, settings, and review components together. Checks cover import/edit/export, conflicts, media/cache, sibling reviews, double-click protection, locking, backup versions, local deletion, sanitization, selector keyboard controls, dialog focus return, pagination, Stop during preview/apply, audio switching, and collapsed diagnostics. The runner checks widths of 320/375/414/768/1440 pixels and captures question, answer, pending, error, and empty review states. Audio events are simulated; recording retrieval uses the production cache implementation. Results and screenshots are written under ignored `test-results/`.

The corrected shared eligibility filter uses `-is:suspended -is:buried -deck:filtered`, matching [Anki's documented search syntax](https://docs.ankiweb.net/manual/searching). Read-only native checks passed on 2026-11-12: due/new searches returned 107/2929 eligible cards, intersections with suspended/buried/filtered cards each returned zero, and a per-note progress query succeeded. A sample of ten returned due cards also had eligible queue/original-deck values. No notes, reviews, templates, or deck settings in the live collection were changed. Browser integration tests simulate the Anki server; they do not constitute a native Anki scheduling or audible playback test. Firefox is production-build checked; the automated browser run uses Chrome.

Latest validation (2026-11-12): 89 unit tests, 44 browser assertions, five responsive widths and five review states per width, no browser exceptions, strict TypeScript, parity for 458 keys across eight languages, and successful Chrome MV3 / Firefox MV2 production builds.
